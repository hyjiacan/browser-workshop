# bws 自动化框架集成开发计划

> 依据文档：[自动化框架集成方案](./自动化框架集成方案.md)
> 目标：将 bws 从「浏览器版本管理工具」扩展为「自动化测试框架的浏览器供应层」
> 核心原则：**bws 不实现自动化测试，bws 提供“被自动化测试的浏览器”**

---

## 一、范围与目标

### 1.1 交付目标

| # | 目标 | 对应方案章节 | 验收标准 |
|---|---|---|---|
| G1 | 统一输出层（`--json` 全局能力） | 第五章 | 所有新命令 `--json` 输出 `{ok,command,data/error}` 信封；非 JSON 时统一对齐格式；元信息走 stderr |
| G2 | 实例注册表 | 4.5 | `<bws-data>/instances.json` 读写带文件锁；损坏可容忍；查询时清理僵尸条目 |
| G3 | `--automation` 开关 | 第三章 | 一条命令完成 CDP 注入、端点发现、驱动管理、信息输出 |
| G4 | CDP 端点暴露 | 3.1/3.9 | Playwright/Puppeteer 能通过 `cdp` 字段连接 |
| G5 | WebDriver 端点暴露 | 3.2/3.9 | Selenium/WebdriverIO 能通过 `webdriver` 字段连接 |
| G6 | 生命周期闭环 | 第四章 | `run --daemon` → `ps` → `stop` 可脚本化，全部支持 `--json` |
| G7 | `where` / `endpoint` 命令 | 2.2/5.5 | Cypress `--browser $(bws where chrome@120)` 可用；`endpoint` 可取实例端点 |
| G8 | 文档与示例 | 第七章阶段13 | 用户可按文档快速接入 |

### 1.2 非目标

- 不实现测试运行器、断言库、报告生成器
- 不替代 Playwright Test / Cypress 的测试组织能力
- 不提供云端 Grid 或分布式调度

### 1.3 现状盘点（开工前）

| 能力 | 状态 | 说明 |
|---|---|---|
| chromedriver 解析/下载/启动（`internal/driver`） | ✅ 已有 | `Resolve`/`Ensure`/`List`/`Uninstall`/`Start` |
| `bws driver` 命令组 | ✅ 已有 | `ls/install/start/uninstall` |
| `run --automation` 拉起驱动 | 🟡 部分 | 已启动驱动并打印 WebDriver，但无 CDP、无注册表、无输出契约 |
| 统一输出层 / `--json` | ❌ 缺失 | `ls` 声明了 `--json` 但未实现 |
| CDP 参数注入与端点发现 | ❌ 缺失 | 无 `--remote-debugging-*`、无 `DevToolsActivePort` 解析 |
| 实例注册表 / `ps` / `stop` | ❌ 缺失 | 无后台实例管理 |
| `where` / `endpoint` 命令 | ❌ 缺失 | — |

> 结论：与方案 1.3 一致 —— **能力已有，只缺接口**。

## 二、阶段划分

将方案的 13 个阶段按依赖关系重组为 6 个可独立验证的工作包（WP）。

```
WP1 统一输出层 ─┬─▶ WP3 端点能力 ─┬─▶ WP4 生命周期闭环 ─▶ WP5 命令与文档
                │                  │
WP2 实例注册表 ─┴──────────────────┘
```

| WP | 覆盖方案阶段 | 内容 | 预估 |
|---|---|---|---|
| WP1 | 阶段1、3 | 统一输出层 + 中文→枚举映射 | 1.5 天 |
| WP2 | 阶段8（注册表部分） | 实例注册表（存储/锁/僵尸清理） | 1.5 天 |
| WP3 | 阶段4、5、7、11 | CDP 注入与端点发现、WebDriver 集成、启动信息输出 | 3 天 |
| WP4 | 阶段8、9、10 | `run --daemon`、`ps`、`stop` 闭环 | 2 天 |
| WP5 | 阶段6、13 | `where`/`endpoint` 命令、文档与示例 | 1.5 天 |
| WP6 | 阶段2、12 | 现有命令按需迁移 + 自动化友好参数注入（复用插件） | 2 天 |

**合计**：约 11.5 人日（较方案原始 15–23 天收敛，因驱动能力已就绪）。

## 三、详细任务分解

### WP1 统一输出层

| 任务 | 文件 | 说明 |
|---|---|---|
| T1.1 输出层实现 | `internal/cli/output.go`（新增） | `Output{JSON,Command,Stdout,Stderr}`；`Object/Groups/Table/Meta/Error/Success/Emit` |
| T1.2 JSON 信封 | 同上 | `{ok,command,data}` / `{ok:false,command,error:{code,message}}`，缩进 2 空格 |
| T1.3 枚举映射 | 同上 | `type`/`channel`/`platform`/`arch` 稳定枚举；中文仅用于人类可读输出 |
| T1.4 字段恒存在 | 同上 + 各命令 | 端点字段用指针，不可用为 `null`，不省略 |

**接口签名**

```go
type Field struct{ Key, Value string }
type Group struct{ Title string; Fields []Field }

type Output struct {
    JSON    bool
    Command string
    Stdout  io.Writer
    Stderr  io.Writer
}

func NewOutput(ctx *Context, command string, json bool) *Output
func (o *Output) Object(fields []Field)          // 单对象键值（对齐）
func (o *Output) Groups(groups []Group)          // 分组 + 缩进键值
func (o *Output) Table(headers []string, rows [][]string)
func (o *Output) Meta(format string, args ...any) // 始终 stderr
func (o *Output) Success(data any) error          // JSON 信封
func (o *Output) Error(code, message string) error
func (o *Output) Emit(data any, human func()) error
```

## 四、测试计划

### 4.1 测试分层

| 层级 | 范围 | 工具 | 目标 |
|---|---|---|---|
| 单元测试 | 输出层、注册表、CDP 参数/发现 | `go test` | 逻辑正确、边界完备 |
| 集成测试 | 命令执行（注入 mock Provider） | `go test` + mock | 命令路径与输出契约 |
| E2E 测试 | 真实浏览器 + 真实框架连接 | 脚本 + 断言 | 用户场景闭环 |
| 手动测试 | 输出观感、跨平台 | 人工 | 体验与兼容性 |

优先级：**P0 阻塞** / **P1 重要** / **P2 一般**。

## 五、风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| `DevToolsActivePort` 在部分版本/平台缺失 | CDP 发现失败 | HTTP `/json/version` 回退；失败不阻断启动 |
| Windows PID 存活检测 API 差异 | 僵尸清理误判 | 使用 `OpenProcess`+`GetExitCodeProcess`，独立构建标签 |
| Firefox CDP 不完整 | 字段缺失 | 按方案 3.5 走 WebDriver；`cdp: null` |
| 输出契约变更破坏脚本 | 兼容性 | 契约即接口，变更需评审；新增字段只增不改 |
| 注册表并发写 | 数据损坏 | 文件锁 + 容错读取 |
