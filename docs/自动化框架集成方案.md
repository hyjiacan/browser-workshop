# bws 自动化框架集成方案

## 一、背景

### 1.1 bws 的现状

`browser-workshop`（bws）是一个用 Go 编写的**多版本浏览器管理工具**，核心能力包括：

- **多版本管理**：同时安装和管理 Chrome、Firefox、Chromium 的多个版本
- **隔离运行**：每个浏览器版本使用独立的 Profile，避免配置冲突和数据串扰
- **插件系统**：支持 Lua 脚本插件，可在浏览器启动时自动修改参数或注入配置
- **代理与指纹隔离**：支持全局代理配置，以及通过 `--fingerprint` 参数降低浏览器指纹被追踪的风险
- **便携模式**：数据存储在 `bws-data/` 子目录，适合 U 盘随身携带

### 1.2 前端自动化的现实需求

前端开发者在日常工作中，经常需要将浏览器用于自动化场景：

- **端到端测试**：用 Playwright、Puppeteer、Selenium 等框架验证页面功能
- **UI 回归测试**：在不同浏览器版本、设备模拟环境下验证界面一致性
- **网络场景测试**：模拟弱网、代理、离线等条件
- **AI 辅助开发**：通过 Playwright MCP 等工具让 AI Agent 操作页面

这些场景的共同基础需求是：**一个干净、隔离、可控、能被外部框架接入的浏览器实例**。而这恰恰是 bws 已有的能力。

### 1.3 当前的问题

bws 已经具备浏览器二进制管理、Profile 隔离、代理和指纹配置等能力，但这些能力目前只面向“人”操作，**缺少面向自动化框架的接入接口**。开发者若要将 bws 用于自动化，仍需：

- 通过 bws 手动启动浏览器，再手动把连接信息告诉框架
- 在 bws 和测试框架之间手工搬运 Profile、端点等参数
- 无法让框架直接按需创建、使用、回收 bws 管理的隔离实例
- **自行记忆并输入 CDP、WebDriver 等底层浏览器参数**

**问题的本质不是能力缺失，而是接口缺失。**

### 1.4 机会

主流自动化测试框架都原生支持**连接到一个已经运行的浏览器实例**：

- Puppeteer 和 Playwright 支持通过 **CDP WebSocket 端点**接入
- Selenium 和 WebdriverIO 支持通过 **Remote WebDriver 协议**接入
- Cypress 支持通过 `--browser` 参数指定**浏览器二进制路径**

bws 不需要实现任何测试逻辑，只需要**暴露标准端点**，就能让这些框架直接使用 bws 管理的浏览器实例。

## 二、目标

### 2.1 总体目标

将 bws 从“浏览器版本管理工具”扩展为 **“自动化测试框架的浏览器供应层”**，让开发者用熟悉的测试框架，直接接入 bws 管理的隔离浏览器实例。

核心原则：**bws 不实现自动化测试，bws 提供“被自动化测试的浏览器”。**

### 2.2 具体目标

| 目标 | 说明 |
|---|---|
| **一个开关开启所有自动化测试能力** | 用户加 `--automation`，bws 自动完成所有相关配置 |
| **CDP 端点暴露** | 自动注入 CDP 参数并发现端点，供 Playwright、Puppeteer 接入 |
| **WebDriver 端点暴露** | 自动管理 driver 进程，供 Selenium、WebdriverIO 接入 |
| **浏览器路径输出** | `bws where` 命令输出二进制路径，供 Cypress 使用 |
| **统一输出契约** | 所有命令支持 `--json`，非 JSON 时统一输出形式 |
| **隔离能力复用** | 每个自动化测试任务使用独立 Profile，Cookie、缓存互不干扰 |
| **生命周期闭环** | `run --daemon` → `ps` → `stop` 形成完整后台实例管理闭环 |

### 2.3 非目标

- 不实现测试运行器、断言库、报告生成器
- 不替代 Playwright Test、Cypress 等框架的测试组织能力
- 不提供云端 Grid 或分布式测试调度

## 三、核心设计：`--automation` 开关

### 3.1 设计理念

用户只需要表达一个意图：“我要跑自动化测试”，bws 负责其余所有细节。

```bash
bws r chrome@120 --automation
```

这一条命令背后，bws 自动完成：

1. 注入 CDP 参数（`--remote-debugging-port=0`、`--remote-debugging-address=127.0.0.1`）
2. 启动浏览器，使用隔离 Profile
3. 发现并解析 CDP WebSocket 端点
4. 拉起对应版本的 chromedriver（如果可用）
5. 注入自动化测试友好的浏览器参数（`--disable-blink-features=AutomationControlled` 等）
6. 输出所有连接信息（Binary / Profile / CDP / WebDriver）

### 3.2 `--automation` 的组成

`--automation` 是以下能力的组合开关：

| 子能力 | 说明 | 可单独控制 |
|---|---|---|
| CDP 端点暴露 | 注入 CDP 参数 + 端点发现 | `--cdp` |
| WebDriver 端点暴露 | 管理 driver 进程 | `--webdriver` |
| 自动化测试参数注入 | 降低自动化检测等 | 通过插件系统 |
| 隔离 Profile | 独立数据目录 | `--profile` |

### 3.3 与子开关的交互规则

| 场景 | 行为 |
|---|---|
| 仅 `--automation` | 开启全部自动化能力 |
| `--automation --cdp` | 等价于 `--automation`，重复指定不报错，行为一致 |
| `--automation --webdriver` | 等价于 `--automation`，重复指定不报错，行为一致 |
| `--cdp` 单独使用 | 仅开启 CDP 端点暴露 |
| `--webdriver` 单独使用 | 仅开启 WebDriver 端点暴露（内部自动注入 CDP 参数作为底层通道） |
| `--cdp --webdriver` | 同时开启两者，等价于 `--automation` 的端点部分 |

**规则**：`--automation` 是子开关的超集，同时指定时以 `--automation` 为准，不产生冲突。

### 3.4 用户参数优先

如果用户自己传了 `--remote-debugging-port=9222`，bws 尊重用户参数，不追加 `=0`，但仍执行端点发现。

规则：**bws 只补充用户没传的参数，不覆盖用户显式传入的参数。**

### 3.5 浏览器支持矩阵

| 浏览器 | CDP 端点 | WebDriver 端点 | 浏览器路径 | 说明 |
|---|---|---|---|---|
| **Chrome** | ✅ 完整支持 | ✅ 完整支持 | ✅ | 主要目标 |
| **Chromium** | ✅ 完整支持 | ✅ 完整支持 | ✅ | 与 Chrome 一致 |
| **Edge** | ✅ 完整支持 | ✅ 完整支持 | ✅ | Chromium 内核，行为一致 |
| **Firefox** | ⚠️ 有限支持 | ✅ 完整支持 | ✅ | CDP 支持不完整，推荐走 WebDriver |
| **其他** | ❌ | ⚠️ 取决于 driver | ✅ | 路径输出始终可用 |

**说明**：`--automation` 当前主要面向 Chromium 系浏览器。Firefox 场景下，CDP 端点字段可能省略，WebDriver 端点仍可用。

### 3.6 字段缺省行为

当某个子能力不可用时，输出中的字段表现如下：

| 场景 | 非 JSON | JSON |
|---|---|---|
| chromedriver 未安装 | 省略 `WebDriver:` 行 | `"webdriver": null` |
| CDP 端点发现失败 | 省略 `CDP:` 行 | `"cdp": null` |
| 两者均不可用 | 只输出 Instance / Binary / Profile | 对应字段为 `null` |

**规则**：字段始终存在于 JSON 结构中，不可用时值为 `null`，便于脚本统一判断。非 JSON 输出中，不可用的字段整行省略。

### 3.7 错误处理

| 错误场景 | 处理方式 |
|---|---|
| CDP 端口被占用 | 若用户未指定端口，bws 使用 `=0` 由系统分配，不会冲突；若用户指定端口被占用，报错退出 |
| 端点发现超时 | 默认超时 10 秒，超时后输出警告（stderr），实例仍可用，`cdp` 字段为 `null` |
| chromedriver 启动失败 | 输出警告（stderr），实例仍可用，`webdriver` 字段为 `null` |
| chromedriver 版本不匹配 | 尝试查找兼容版本，找不到则输出警告，`webdriver` 字段为 `null` |
| 浏览器启动失败 | 报错退出，退出码非 0 |
| Profile 被占用 | 报错退出，提示用户更换 Profile 名称或停止占用实例 |

**规则**：端点相关能力失败时，**不阻断浏览器启动**，只影响对应字段的值。浏览器本身启动失败才终止流程。

### 3.9 框架接入方式

**Playwright**：
```javascript
const browser = await chromium.connectOverCDP('http://127.0.0.1:9222');
```

**Puppeteer**：
```javascript
const browser = await puppeteer.connect({ browserURL: 'http://127.0.0.1:9222' });
```

**Selenium**：
```python
driver = webdriver.Remote(command_executor='http://127.0.0.1:9515')
```

**Cypress**：
```bash
cypress run --browser $(bws where chrome@120)
```

**说明**：Cypress 场景下 `--automation` 仍可正常使用，其输出中的 `cdp` / `webdriver` 字段对 Cypress 无用，Cypress 只消费 `binary` 字段。

## 四、后台实例生命周期闭环

### 4.1 设计目标

`run --daemon` 启动后台实例，`ps` 查看后台实例，`stop` 停止实例，三者形成完整闭环，每个环节都支持 `--json`，可脚本化。

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  run        │────▶│  ps          │────▶│  stop       │
│  --daemon   │     │  查看后台实例 │     │  停止实例    │
│  启动后台实例 │     │              │     │             │
└─────────────┘     └──────────────┘     └─────────────┘
       │                                        ▲
       │                                        │
       └────────────── 实例注册表 ──────────────┘
```

### 4.2 `run --daemon`

**命令设计**：

```bash
bws r chrome@120 --automation --daemon --profile test-01
```

**非 JSON 输出**：

```
Instance:  bws-chrome-120-test-01
Binary:    C:\Users\xxx\.bws\browsers\chrome\120\chrome.exe
Profile:   C:\Users\xxx\.bws\profiles\chrome\120\test-01
CDP:       ws://127.0.0.1:54321/devtools/browser/xxxxx
WebDriver: http://127.0.0.1:9515
PID:       12345
```

**行为定义**：

| 行为 | 前台（默认） | `--daemon` |
|---|---|---|
| 阻塞终端 | 是，等待浏览器退出 | 否，启动成功即返回 |
| 实例信息输出 | 启动后输出 | 启动后输出，随后 bws 退出 |
| 浏览器生命周期 | 随 bws 进程 | 独立于 bws 进程 |
| 实例注册 | 可选 | 写入实例注册表，供 `ps` / `stop` 查询 |
| 日志 | stdout / stderr | 重定向到日志文件 |

**实例命名规则**：

```
bws-<browser>-<version>[-<profile>]
```

例如：
- `bws r chrome@120 --daemon` → `bws-chrome-120`
- `bws r chrome@120 --daemon --profile test-01` → `bws-chrome-120-test-01`

如果同名实例已存在，报错退出，提示用户先 `bws stop <instance>` 或换 Profile。

**JSON 输出**：

```json
{
  "ok": true,
  "command": "run",
  "data": {
    "instance": "bws-chrome-120-test-01",
    "binary": "C:\\Users\\xxx\\.bws\\browsers\\chrome\\120\\chrome.exe",
    "profile": "C:\\Users\\xxx\\.bws\\profiles\\chrome\\120\\test-01",
    "cdp": "ws://127.0.0.1:54321/devtools/browser/xxxxx",
    "webdriver": "http://127.0.0.1:9515",
    "pid": 12345,
    "daemon": true
  }
}
```

### 4.3 `ps` 子命令

**命令设计**：

```bash
# 列出所有后台实例
bws ps
```

**非 JSON 输出**：

```
NAME                     BROWSER   VERSION          PROFILE     PID     CDP
bws-chrome-120-test-01   chrome    120.0.6478.115   test-01     12345   ws://127.0.0.1:54321/...
bws-firefox-115          firefox   115.0            default     12346   -
```

规则：
- 无实例时输出 `No running instances.`
- 表格列宽动态计算
- CDP 过长时截断，完整值通过 `--json` 或 `bws endpoint` 获取

**JSON 输出**：

```json
{
  "ok": true,
  "command": "ps",
  "data": {
    "instances": [
      {
        "name": "bws-chrome-120-test-01",
        "browser": "chrome",
        "version": "120.0.6478.115",
        "profile": "test-01",
        "pid": 12345,
        "status": "running",
        "cdp": "ws://127.0.0.1:54321/devtools/browser/xxxxx",
        "webdriver": "http://127.0.0.1:9515",
        "binary": "C:\\Users\\xxx\\.bws\\browsers\\chrome\\120\\chrome.exe",
        "startedAt": "2026-09-30T10:00:00Z"
      },
      {
        "name": "bws-firefox-115",
        "browser": "firefox",
        "version": "115.0",
        "profile": "default",
        "pid": 12346,
        "status": "running",
        "cdp": null,
        "webdriver": null,
        "binary": "C:\\Users\\xxx\\.bws\\browsers\\firefox\\115\\firefox.exe",
        "startedAt": "2026-09-30T10:05:00Z"
      }
    ]
  }
}
```

**与 `ls` 的区别**：

| 命令 | 对象 | 说明 |
|---|---|---|
| `bws ls` | 已安装的浏览器版本 | 磁盘上的二进制 |
| `bws ps` | 运行中的实例 | 内存/注册表中的进程 |

两者不重叠，各自独立。

**僵尸实例处理**：

- 查询时检查 PID 是否仍存活
- 不存活的实例自动从注册表移除，并标记为 `stale`（输出警告到 stderr）
- JSON 输出中不包含已失效实例

### 4.4 `stop` 子命令

**命令设计**：

```bash
# 停止指定实例
bws stop bws-chrome-120-test-01

# 停止所有实例
bws stop --all
```

**行为定义**：

| 行为 | 说明 |
|---|---|
| 发送终止信号 | 先尝试优雅退出，超时后强制终止 |
| 清理注册表 | 从实例注册表移除 |
| 保留 Profile | Profile 数据不删除，用户可手动清理或复用 |
| 停止 driver | 如果实例关联了 chromedriver，一并停止 |
| 输出 | `Stopped: bws-chrome-120-test-01` |

**非 JSON 输出**：

```
Stopped: bws-chrome-120-test-01
```

**JSON 输出**：

```json
{
  "ok": true,
  "command": "stop",
  "data": {
    "stopped": ["bws-chrome-120-test-01"],
    "failed": []
  }
}
```

**错误处理**：

| 场景 | 处理方式 |
|---|---|
| 实例不存在 | 报错退出，退出码非 0 |
| 进程已退出但注册表未清理 | 清理注册表，输出 `Stopped: <name> (already exited)` |
| 强制终止失败 | 输出警告，`failed` 数组包含实例名，退出码非 0 |

### 4.5 实例注册表

**存储位置**：

```
<bws-data>/instances.json
```

**结构**：

```json
{
  "instances": [
    {
      "name": "bws-chrome-120-test-01",
      "browser": "chrome",
      "version": "120.0.6478.115",
      "profile": "test-01",
      "pid": 12345,
      "binary": "C:\\Users\\xxx\\.bws\\browsers\\chrome\\120\\chrome.exe",
      "profileDir": "C:\\Users\\xxx\\.bws\\profiles\\chrome\\120\\test-01",
      "cdp": "ws://127.0.0.1:54321/devtools/browser/xxxxx",
      "webdriver": "http://127.0.0.1:9515",
      "driverPid": 12347,
      "startedAt": "2026-09-30T10:00:00Z",
      "daemon": true
    }
  ]
}
```

**并发安全**：

- 写入时加文件锁
- 读取时容忍损坏（解析失败视为空注册表，并输出警告到 stderr）
- 启动时清理 PID 已失效的条目

## 五、统一输出契约

### 5.1 设计原则

| 原则 | 说明 |
|---|---|
| **所有命令支持 `--json`** | 通用出口，无需为每个命令单独设计 |
| **非 JSON 时统一输出形式** | 所有命令遵循同一套结构 |
| **stdout 只放内容，stderr 只放元信息** | 启动横幅、配置提示走 stderr |
| **中文只用于人类可读输出** | JSON 中描述性字段使用稳定枚举值 |

### 5.2 非 JSON 输出形式

**分组 + 缩进键值**（如 `info`、`where`、`endpoint`、启动信息）：

```
chrome@126.0.6478.115
  类型:     系统安装
  渠道:     stable

chrome@126.0.6478.182（远程更新可用）
  渠道:         stable
  平台:         windows
  架构:         amd64
  下载链接:     http://172.16.53.2:2002/api/v1/download/...

  使用 'bws i chrome@126.0.6478.182' 升级到此版本。
```

规则：
- 同一分组内，键名右对齐到该分组最长键名的显示宽度
- 冒号统一用半角 `:`，后跟一个空格
- 分组之间保留一个空行
- 操作建议作为独立段落

**对齐表格**（如 `ls`、`ps`）：

```
NAME                  BROWSER   VERSION          STATUS
bws-chrome-120        chrome    120.0.6478.115   running
bws-firefox-115       firefox   115.0            stopped
```

**操作反馈**（如 `install`、`remove`、`stop`）：

```
Installed: chrome@120
Path:      C:\Users\xxx\.bws\browsers\chrome\120
```

### 5.3 JSON 输出结构

成功：

```json
{
  "ok": true,
  "command": "info",
  "data": { ... }
}
```

失败：

```json
{
  "ok": false,
  "command": "info",
  "error": {
    "code": "NOT_FOUND",
    "message": "chrome@120 is not installed"
  }
}
```

### 5.4 中文到枚举的映射

| 非 JSON | JSON |
|---|---|
| 系统安装 | `"type": "system"` |
| 渠道: stable | `"channel": "stable"` |
| 平台: windows | `"platform": "windows"` |
| 架构: amd64 | `"arch": "amd64"` |
| 远程更新可用 | `"updateAvailable": true` |

### 5.5 各命令 JSON 输出示例

**`bws info gc@126 --json`**：

```json
{
  "ok": true,
  "command": "info",
```

## 八、关键设计原则

1. **一个开关，全部就绪**：`--automation` 是自动化测试场景的单一入口，用户不需要记忆多个子开关。

2. **bws 不感知框架**：bws 只暴露标准端点，不需要知道连过来的是 Playwright 还是 Selenium。

3. **用户参数优先**：bws 只补充用户未显式传入的参数，不覆盖用户的选择。

4. **端点即凭证**：CDP 端点具有高权限，应绑定到 loopback 地址、使用非默认 user-data 目录。

5. **复用已有能力**：隔离 Profile、多版本管理、插件系统是 bws 的核心优势，自动化集成只是“暴露接口”。

6. **渐进式集成**：先做 CDP（覆盖面最广），再集成 WebDriver，最后处理 Cypress 的特殊情况。

7. **不重复造轮子**：不实现测试运行器、断言库、报告生成器。

8. **stdout 只放内容，stderr 只放元信息**：保证管道和重定向的干净输出。

9. **中文只用于人类可读输出**：JSON 中描述性字段使用稳定枚举值。

10. **`--json` 是全局能力**：在 CLI 框架层统一实现，所有命令自动获得。

11. **输出即接口**：非 JSON 和 JSON 都是对外契约，变更需谨慎。

12. **路径即接口**：`where` 命令和启动时的路径输出，是 bws 与 Cypress 等框架的衔接方式。

13. **端点失败不阻断启动**：CDP/WebDriver 相关能力失败时，浏览器实例仍可用，对应字段为 `null`，便于脚本容错。

14. **字段始终存在**：JSON 输出中，端点字段始终存在，不可用时为 `null`，不省略字段。

15. **生命周期闭环**：`run --daemon` → `ps` → `stop` 形成完整闭环，每个环节都支持 `--json`，可脚本化。

16. **注册表是唯一事实来源**：后台实例的状态以注册表为准，查询时校验 PID 存活，自动清理僵尸条目。

17. **停止不删数据**：`stop` 只停止进程、清理注册表，不删除 Profile 数据，用户可复用或手动清理。

18. **能力已有，只缺接口**：bws 已有的浏览器管理、Profile 隔离、环境注入能力，通过 `--automation` 暴露给框架，而不是重新实现。
